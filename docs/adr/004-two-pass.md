# ADR-004: 실시간 패스와 최종 패스의 분리

- 상태: 제안
- 날짜: 2026-11-02

## 맥락
원칙 7: 실시간 자막과 최종 편집 자막을 구분한다. Whisper는 스트리밍 전용 모델이 아니고 ✅, 로컬 소형 번역 모델의 품질은 한계가 있다. 실시간 결과는 조금 부정확해도 최종 편집에서 고칠 수 있어야 한다.

## 선택지
1. 실시간 결과만 사용 — 품질이 가장 낮고 편집 부담이 크다.
2. 실시간에도 최고 품질 모델 사용 — 지연이 커서 오버레이 목적에 맞지 않는다.
3. **2-패스**: 실시간은 저지연·소형 모델, 종료 후 저장된 오디오로 최고 품질 재인식·문맥 번역.

## 결정
**2-패스**를 채택한다.

| | 실시간 패스 | 최종 패스 |
|---|---|---|
| 시점 | 캡처 중 | Stop 이후 (Processing) |
| ASR | turbo급, 발화 단위 | 최고 품질 모델, 전체 오디오 |
| 번역 | 소형·짧은 문맥 | 대형·전체 문맥·10줄 배치 |
| 결과 표식 | `origin=realtime` | `origin=final` |

규칙:
- 사용자가 수정한 줄(`user_edited`)은 최종 패스가 덮어쓰지 않는다.
- 최종 패스는 Job으로 기록하고 체크포인트에서 재개한다.
- 사용자는 「건너뛰고 실시간 결과로 편집」을 선택할 수 있다 (Q7).
- 실시간 ASR이 밀리면 따라잡기 모드로 건너뛴 구간을 최종 패스가 채운다.

## 결과
- 오디오를 종료 후에도 보존해야 하므로 임시 오디오 저장이 필수다 (원칙 5.1). 이는 「SRT 내보내기 ≠ 완료」와 맞물린다.
- 최종 패스 소요 시간(1시간 영상 기준)은 ❓ — Phase 0에서 측정해 Processing UX를 확정한다.
- 정확도 목표를 두 패스에 따로 둔다 (PRD §8).
