# ADR-006: 재생 모드와 자동 싱크

- 상태: 제안 (Phase 0 실험 결과로 확정)
- 날짜: 2026-11-02

## 맥락
Q2 답변: 저장된 자막(또는 불러온 SRT)을 나중에 같은 영상을 다시 볼 때 **SubBridge의 오버레이로** 영상 위에 띄우고 싶다. 초기 설계에는 이 기능이 없었다(오버레이는 녹음 중에만 동작).

문제: SubBridge는 영상 화면을 볼 수 없어서 영상이 지금 몇 분 몇 초인지 모른다. 사용자는 Q19에서 **자동 싱크를 기본으로, 수동은 미세조정용**으로 원했다(수동만으로는 불편).

## 선택지
| | 방법 | 장점 | 단점 / 미확인 |
|---|---|---|---|
| A | **오디오 지문**: 캡처(또는 처리) 때 짧은 구간별 지문을 만들어 프로젝트에 저장. 재생 때 들은 소리의 지문을 대조 | ASR 없이 가볍고 빠를 것으로 예상, 언어와 무관 | 구현체·라이선스 ❓. 같은 영상이어도 광고·버전·더빙이 다르면 실패 가능 ❓. 불러온 SRT에는 지문이 없다 |
| B | **ASR 텍스트 매칭**: 재생 때 실시간 ASR로 대사를 인식해 저장된 자막 텍스트와 퍼지 매칭 | 지문 없는 SRT·다른 버전에도 동작 | 위치를 찾기까지 시간이 걸림, 비슷한 대사에서 오락 ❓, ASR 상시 구동 |
| C | **수동**: 단축키로 시작·보정 | 단순·확실 | 사용자가 불편하다고 함 → 보정용으로만 |
| D | 영상 앱에서 재생 위치를 직접 읽기 (확장·접근성) | 정확 | 사이트마다 다르고 권한 부담, 단일 앱 원칙에 어긋남 → 채택 안 함 |

## 결정 (기본안)
- SubBridge가 만든 프로젝트는 **A**, 불러온 SRT나 A가 실패한 경우는 **B**, 어느 경우에나 **C(수동 미세조정)** 를 함께 제공한다.
- 위치를 찾기 전에는 자막을 띄우지 않는다. 되감기·건너뛰기로 일치 위치가 시계에서 벗어나면 다시 찾는다.
- 수동 보정값(`playback_adjust_ms`)은 자동 결과 위에 더해지고 프로젝트에 저장된다.
- 재생 모드는 프로젝트 수명주기 상태와 오디오 삭제에 영향을 주지 않는다.

## 조건과 폴백
- **Phase 0에서 A·B의 위치 찾기 시간, 오차, 오락(잘못된 위치)을 측정하는 것이 가장 먼저 할 실험이다.**
- 둘 다 쓸 만하지 않으면 **수동을 기본으로 바꾸고 사용자에게 보고**한다. 이 경우 재생 모드는 「시작 단축키 + 보정」 방식이 된다.
- 보호된 오디오가 들리지 않는 서비스에서는 자동 싱크가 불가능하므로(R1) 수동을 쓴다.

## 결과
- A를 채택하면 지문을 만들어 저장해야 한다 → `SyncFingerprint` 엔티티(DATA_MODEL)와 원칙 10과의 관계 결정(Q20)이 필요하다.
- 재생 모드는 캡처와 같은 앱 단위 소스 선택(Q6)·권한을 쓴다.
- SRT 가져오기가 필요하다 (`Project.kind=imported`, `Segment.origin=import`).
- 시간 정합 위험(R4)은 줄지만, 자동 싱크 실현성이라는 새 위험(R14)이 생긴다.
