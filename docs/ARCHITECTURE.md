# SubBridge 아키텍처

> 근거 표시: ✅ 1차 출처 / ◐ 2차 출처 / ❓ 미확인. 구현 코드가 아닌 개념 설계다.

## 2. 모듈 책임과 인터페이스

| 모듈 | 책임 | 입력 → 출력 |
|---|---|---|
| CaptureBackend (OS별) | 소스 목록, 시작·정지, 권한 상태 추정, 장치 변경 알림 | 소스 선택 → PCM 프레임(원본 샘플레이트) + 이벤트 |
| ChunkWriter | 청크 파일 쓰기·봉인, 주기적 fsync, 체크섬, DB 등록 | PCM → AudioChunk 행 |
| AudioPipeline | 리샘플(16k mono), 레벨 미터, VAD | PCM → 발화 구간 |
| AsrProvider | 구간 인식 (언어, 이전 문맥 프롬프트) | 오디오 구간 → 텍스트 + 시간 + 신뢰도 |
| Stabilizer | 잠정/확정 판정, 경계 중복 제거, 환각 필터 | ASR 결과 → Segment 이벤트 |
| TranslationProvider | 배치 번역 (줄 ID 보존, 문맥, 용어집, 존대 정책) | 줄 목록 → 줄별 번역 |
| JobQueue | 최종 패스·재번역·peaks·내보내기·오디오 삭제. 체크포인트로 재개 | Job 행 → 결과 |
| StateMachine | 상태 전이 검증·기록, 진입 조건 확인 | 이벤트 → 전이 or 거부 |
| Exporter | 형식별 직렬화 | Segment + Translation → 파일 |

모든 Provider는 **능력(capabilities) 선언**을 붙인다 (스트리밍 여부, 지원 언어, 문맥 길이, 오프라인 여부). UI는 그 선언을 보고 옵션을 켜고 끈다.
Provider를 교체해도 파이프라인이 바뀌지 않는 것이 원칙 6의 구현이다.

## 3. 오디오 흐름·큐·백프레셔

- 캡처 콜백은 실시간 스레드다 — 메모리 할당·락·I/O를 하지 않는다. lock-free 링버퍼에 넣기만 한다.
- **디스크 쓰기는 ASR보다 우선이다.** ChunkWriter는 ASR이 느려도 막히지 않는다.
- 청크: 30초 단위 파일, 약 2초마다 flush+fsync → 크래시가 나도 잃는 오디오는 2초 이하(목표).
- 시간 기준 = **전역 샘플 인덱스(16kHz)**. 벽시계를 쓰지 않으므로 누적 드리프트가 없다. ms 변환은 내보낼 때만 한다.
- 실시간 ASR이 밀리면(대기열 > N초) **따라잡기 모드**: 오래된 구간의 실시간 인식을 건너뛴다(오디오는 디스크에 있다). 건너뛴 구간은 최종 패스가 메운다. 오버레이에 「지연 중」을 표시한다.
- 모든 채널은 크기가 제한된다(bounded). 넘치면 오래된 잠정 결과부터 버린다. 확정 결과는 버리지 않는다.

## 4. 2-패스 (ADR-004)

| | 실시간 패스 | 최종 패스 |
|---|---|---|
| 시점 | 캡처 중 | Stop 이후 (Processing) |
| ASR | turbo급, 발화 단위 | 최고 품질 모델로 저장된 오디오 전체 재인식 |
| 번역 | 소형·짧은 문맥, 문장 끝(。？) 또는 2줄 단위 | 대형·전체 문맥, 용어집, 10줄 배치 |
| 결과 | `origin=realtime` | `origin=final` — **사용자가 수정한 줄은 덮어쓰지 않는다** |

## 5. 상태 머신

```text
            ┌──────── 재개 ────────┐
 Ready ──▶ Recording ⇄ Paused ────┤
              │          │        │
           (이상)      (이상)      │
              ▼          ▼        │
           Interrupted ───────────┘ (복구 후 재개 = 새 세션)
              │ (마치기)
 Recording/Paused ── Stop ──▶ Processing ──▶ Editing ──▶ Completed
                                  │(건너뛰기)    ▲   │ (오디오 삭제)
                                  └─────────────┘   └ 텍스트 편집은 허용, 오디오 기능은 꺼짐
 내보내기 상태(별도 축): 없음 / 최신(revision 일치) / 오래됨(내보낸 뒤 수정됨)
```

| 상태 | 진입 조건 | 복구 동작 |
|---|---|---|
| Ready | 프로젝트 생성, 오디오 없음 | — |
| Recording | 소스 선택 · 권한 · 디스크 여유 ≥ 기준. ASR이 준비되지 않아도 시작은 할 수 있다 | 크래시 → 다음 실행 때 Interrupted |
| Paused | 사용자 일시정지, 절전 직전, 장치 변경, 디스크 경고 — 현재 청크 봉인 | 그대로 재개 가능 |
| Interrupted | 시작할 때 DB 상태가 Recording/Paused/Processing인데 정상 종료 표시가 없음. 또는 실행 중 치명적 캡처 오류 | 청크 검증 → 마지막 WAV 헤더 복구 → DB 대조 → 「이어서 녹음 / 마치고 처리」 선택 |
| Processing | Stop | Job 체크포인트에서 재개. 엔진이 실패하면 건너뛰고 Editing으로 갈 수 있다 |
| Editing | 처리 완료 또는 건너뛰기 | 편집 1건 = 트랜잭션 1건 (자동 저장) |
| Completed | **사용자가 명시적으로 「작업 완료」를 선택** + 진행 중 Job 없음 + DB 무결성 검사 통과 + 미저장 편집 없음 | 오디오 삭제는 2단계 Job (§7) |

**`Exported`는 수명주기 상태가 아니다.** 내보내기 상태는 `Export.revision_at_export == Project.revision`으로 계산한다 (ADR-005).
내보내기는 어떤 상태 전이도 일으키지 않고, **오디오를 삭제하지 않는다.**
재생 모드(§13)도 수명주기 상태를 바꾸지 않는다.

## 7. 임시 오디오 관리

- 녹음 전 예상 용량을 안내한다 (16kHz mono s16 ≈ 115MB/h). Editing에서는 프로젝트별 오디오 용량을 표시한다.
- **완료 시 삭제 (2단계)**: ① `audio_status=deleting` 기록 (`synchronous=FULL`) → ② 파일 삭제 → ③ `deleted` 기록. 중간에 크래시가 나면 다음 실행 때 이어서 지운다(멱등).
- 삭제 트리거는 Completed뿐이다.
- 삭제 방식(즉시 / 휴지통 / 유예 기간): `[결정 대기: Q9]`

## 8. 오류·복구 시나리오

| 상황 | 감지 | 동작 |
|---|---|---|
| 녹음 중 앱 종료 | 종료 요청 | 확인 창 → 청크 봉인 → Paused로 저장 → 다음 실행 때 「이어서 / 마치기」 |
| 절전 | willSleep 알림 / 깨어난 뒤 샘플 수와 벽시계 차이 | 자동 Paused(사유: 절전). 알림 없이 잠들었으면 Interrupted |
| 비정상 종료 | `.lock` 하트비트 + DB 상태 | Interrupted 복구 절차. 손실 ≤ flush 간격 |
| 캡처 오류 (장치 분실, 권한 철회, 탭 무효) | 콜백 오류, 속성 리스너 | 백오프하며 자동 재연결 3회 → 실패하면 Paused + 알림 |
| 대상 앱 종료·재시작 (브라우저 재실행 등) | 프로세스 종료 알림 / 탭 무효 | 번들 ID로 소스를 다시 찾는다(3회, 백오프). 못 찾으면 Paused + 「다시 재생한 뒤 재개」 안내 |
| 무음 지속 | 디지털 0이 N초 | 경고만 (진짜 무음일 수 있다). 권한·DRM 안내 링크 |
| 번역 모델 무응답 | 요청 타임아웃, 헬스체크 | 재시도 2회 → 서킷 브레이커. 오버레이는 원문만. `pending`으로 표시해 최종 패스에서 채운다. 사이드카 자동 재시작 |
| 디스크 부족 | 10초마다 여유 공간 확인, ENOSPC, SQLITE_FULL | 경고 기준 → 알림. 위험 기준 → 자동 Paused + 봉인. DB 쓰기 실패 시 편집을 메모리 대기열에 두고 재시도 |
| ASR 적체 | 대기열 길이 | 따라잡기 모드 (§3) |

## 9. 플랫폼별 차이

공통 코드: 파이프라인 · ASR · 번역 · 저장 · 편집기 · 내보내기 · 상태 머신.
OS별 코드: `CaptureBackend` 구현 · 권한 온보딩 · 절전 알림 · 오버레이 창 속성 · 패키징.

| OS | 캡처 | 권한 | 알려진 제약 |
|---|---|---|---|
| macOS (**26+**, Q3) | Core Audio Process Tap ✅ (ScreenCaptureKit는 쓰지 않는다 — ADR-001) | 시스템 오디오 녹음 권한. 확인 공개 API 없음 → 무음으로만 판별 ✅ | 출력 장치 변경 시 탭 재구성 ❓ |
| Windows | WASAPI 루프백. 앱 단위는 `PROCESS_LOOPBACK` (build 20348+) ✅ | 별도 권한 없음 | DRM 보호 스트림은 루프백 불가 ✅ |

## 10. macOS 오버레이 미해결 사항 ❓

전체화면 영상의 Space 위에 오버레이가 뜨는지 확인되지 않았다. NSWindow `fullScreenAuxiliary` 설정이 필요할 수 있다. Phase 0 항목 ⑥에서 검증한다.

## 11. 내보내는 SRT의 시간 기준

SubBridge는 오디오만 캡처하므로 영상의 재생 위치를 알 수 없다.

- **SRT 시간 = 캡처가 진행된 시간.** SubBridge를 일시정지한 구간은 타임라인에서 빠진다.
- 영상과 어긋나면 편집기의 **싱크 맞추기**(한 줄의 실제 영상 시간을 입력 → 전체 이동 값 계산), **전체 이동**, **지점별 간격 삽입/삭제**로 보정한다.
- 캡처를 영상 처음부터 1.0배속으로 하면 어긋남이 가장 적다 (시작 전 안내).
- 이 기준은 내보낸 SRT를 **다른 플레이어에서 쓸 때**를 위한 것이다.
- SubBridge 안에서 자막을 영상 위에 다시 띄우는 재생 모드는 §13, 결정 근거는 ADR-006.

## 12. 앱 단위 캡처 (Q6)

MVP는 **앱 단위**로만 캡처한다. 「시스템 전체」는 만들지 않는다.

- **소스 목록**: 지금 소리를 내는 앱을 앱(번들) 단위로 묶어 보여 준다. 브라우저는 실제로 소리를 내는 프로세스가 본체가 아니라 헬퍼 프로세스일 수 있어서, 번들 기준으로 헬퍼를 묶어야 한다 ❓ (Phase 0에서 Chrome·Safari·Firefox·Arc로 확인).
- **자기 소리 제외**: SubBridge 자신의 소리는 항상 뺀다 (편집기 재생음이 다시 캡처되는 것을 막는다).
- **탭 단위는 불가**: Core Audio 탭은 프로세스 단위 API라서 브라우저 탭 하나만 골라 캡처할 수 없다. 같은 브라우저의 다른 탭 소리가 섞일 수 있다 — 소스 선택 화면에 안내한다. (브라우저의 오디오 프로세스 구조는 ❓)
- **이점**: 시스템 알림음·메신저 소리가 섞이지 않는다.
- **대상 앱이 꺼졌다 켜지면** 프로세스 ID가 바뀐다. 번들 ID로 다시 찾는다 (§8).

## 13. 재생 모드 (Playback)

완성한 프로젝트(또는 불러온 SRT)를 SubBridge 오버레이로 영상 위에 다시 띄운다. **SubBridge는 영상을 재생하지 않는다** — 다른 앱(브라우저·플레이어)이 재생하는 영상 위에 자막만 띄운다. (Q2, ADR-006)

```text
영상 앱의 소리 ─▶ SyncSource(캡처와 같은 Core Audio 탭, 앱 단위)
                    ├─▶ [A] 지문 매처 ─┐
                    └─▶ [B] ASR 텍스트 매처 ─┤
                                              ▼
                        ReplayClock(영상 위치 추정) ─▶ 저장된 Segment 조회 ─▶ 오버레이
                                              ▲
                              수동 미세조정(playback_adjust_ms)
```

- **프로젝트 상태와 무관**: Editing·Completed 어느 쪽에서도 열 수 있고, 상태나 오디오 삭제에 영향을 주지 않는다. 자막만 있으면 되므로 오디오가 삭제된 프로젝트에서도 동작한다.
- **같은 소스 선택·권한**: 앱 단위 선택(Q6)과 오디오 권한을 캡처와 똑같이 쓴다. 보호된 오디오가 들리지 않는 서비스에서는 자동 싱크가 불가능하다 (R1) → 수동 시작·보정으로 쓸 수 있게 한다.
- **싱크 상태**: 듣는 중 → 잠금(위치 추정, 자막 표시) → 재동기(되감기·건너뛰기 감지) → 정지(소리가 없어 시계 정지, ❓). 잠금 전에는 자막을 띄우지 않는다.
- **자동 싱크 후보와 기본안은 PIPELINE §10.** 모두 Phase 0 실험 전까지 실현 가능성이 확인되지 않았다 ❓.
- **수동 미세조정**: `playback_adjust_ms`가 자동 싱크 결과 위에 더해지고 프로젝트에 저장된다. 「지금 이 대사에 맞추기」로 위치를 직접 지정할 수도 있다 (UI_UX §13).
- **불러온 SRT**: 프로젝트(`kind=imported`)로 들어오며 오디오·지문이 없다 → ASR 텍스트 매칭([B])만 가능하다.
- **자원**: 재생 모드는 번역이 필요 없다(저장된 번역 사용). 필요한 것은 캡처, 지문 또는 ASR, 오버레이뿐이다.
