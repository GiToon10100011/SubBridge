# SubBridge PRD

> 상태: 초안 v5 (2026-11-02, Q1~Q8·Q18·Q19 답변 반영. 재생 모드 추가). 미결정 항목은 `[결정 대기: Qn]`으로 표시한다. 질문 목록은 문서 끝 §9.
> 근거 표시: ✅ 1차 출처로 확인 / ◐ 2차 출처·사용자 보고 / ❓ 확인 못 함 (Phase 0에서 실측)

## 1. 한 줄 정의

컴퓨터에서 재생되는 영상의 **오디오만** 캡처해 음성 인식 → 번역 → 실시간 이중 자막 → 편집 → SRT 내보내기까지 한 앱에서 처리하는 로컬 우선 데스크톱 앱.

## 1.1 자막 출력과 재생 모드

- **캡처하는 동안의 실시간 자막**은 SubBridge 자체 오버레이가 맡는다 (Q18).
- 캡처가 끝나면 편집한 뒤 **SRT**(원문/번역/이중)로 내보낼 수 있다.
- **재생 모드 (Q2)**: 나중에 같은 영상을 다시 볼 때, SubBridge가 저장된 자막(또는 불러온 SRT)을 같은 오버레이로 영상 위에 띄운다. SubBridge는 영상을 재생하지 않는다 — 다른 앱이 재생하는 영상 위에 자막만 띄운다.
- 재생 모드의 영상 위치는 **자동 싱크**(영상 소리를 듣고 위치를 찾는다)를 기본으로 하고, 어긋나면 수동으로 미세조정한다 (Q19). 자동 싱크의 실현 가능성은 확인되지 않았다 ❓ — Phase 0에서 가장 먼저 실험하고, 안 되면 수동을 기본으로 바꾼다 (ADR-006).

## 2. 사용자와 사용 사례

- 일본 OTT에서 일본 드라마를 시청하며 한국어 이중 자막 제작
- 영어 강의를 한국어 자막으로 변환
- 해외 YouTube 영상의 다국어 자막 제작
- 외국 영화·인터뷰의 원문과 번역문 생성
- 외국어 콘텐츠를 학습 목적으로 활용

특정 언어에 종속되지 않는 범용 자막 제작 도구를 지향한다. 일본어 → 한국어를 먼저 검증한다.

## 3. 제품 원칙

1. 여러 프로그램 설치를 요구하지 않는 단일 데스크톱 앱.
2. 영상 파일을 요구하지 않는다.
3. 영상 자체를 다운로드하거나 저장하지 않는다.
4. 오디오만 캡처하고 처리한다.
5. 기본 기능은 무료 로컬 처리로 제공한다.
6. 음성 인식·번역 엔진은 교체 가능한 구조로 둔다.
7. 실시간 자막과 최종 편집 자막을 구분한다.
8. 작업 중단·재개를 지원한다.
9. SRT 내보내기와 프로젝트 완료는 별개의 동작이다.
10. 프로젝트 완료 후 임시 오디오만 삭제하고 자막 프로젝트는 보존한다.
11. macOS를 먼저 개발하되 Windows·Linux 확장을 고려한다.

## 4. 비목표 (하지 않는 것)

- DRM 우회, OTT 콘텐츠 다운로드, 보호된 오디오의 캡처 우회.
- 영상 파일 저장·재인코딩.
- 자막 공유·업로드 기능 (번역물은 2차적저작물일 수 있다).
- 별도 가상 오디오 드라이버(BlackHole 등) 설치를 요구하는 방식.
- SubBridge 안에서 영상을 재생하는 기능 (재생 모드는 다른 앱의 영상 위에 자막만 띄운다).

## 5. 범위

| 구분 | 포함 |
|---|---|
| **MVP (v0.1, macOS 전용)** | 앱 단위 오디오 캡처(일시정지·재개·레벨·경과시간) · 크래시 안전 청크 저장 · 실시간 ASR(잠정/확정) · 실시간 번역 · 이중 자막 오버레이(3가지 표시 모드, 글꼴 크기·색·투명도·위치, 항상 위, 단축키) · **재생 모드**(저장된 자막·불러온 SRT를 오버레이로 표시, 자동 싱크 + 수동 미세조정) · 최종 패스 · 편집기(목록, 원문/번역 편집, 시간 편집, 분할/병합, 행 클릭 재생, 구간 반복, 파형, 수정 표시, 자동 저장, undo) · 선택 구간 재번역 · SRT 3종 (전역 오프셋·싱크 맞추기 포함) · 상태 머신 · 복구 · 완료 시 오디오 삭제 |
| v0.2 | 용어집 · 자막 품질 검사(CPS 등) · 무음 압축 · VTT |
| v0.3 | Windows (WASAPI 시스템 + 앱 단위 루프백) · 화자 구분 |
| v0.4 | Linux (PipeWire, X11 오버레이) |
| v0.5+ | 클라우드 Provider (BYOK) · 파일 불러오기 (FFmpeg 재검토) · 강제 정렬 · 학습 기능 (Q14) |

플랫폼 하한은 **macOS 26 · Apple Silicon**이다 (Q3, Q4). OS 제약이 없으므로 Apple SpeechAnalyzer·Translation은 Phase 0 벤치 결과에 따라 MVP에 편입할 수 있다 (v0.2에서 앞당김 가능). Windows·Linux 확장 방침은 그대로다.

## 6. 핵심 요구사항 요약

각 항목의 설계는 ARCHITECTURE / PIPELINE / UI_UX에 있다.

- **캡처**: 소스 선택, 시작·종료, 일시정지·재개, 경과 시간, 입력 레벨, 청크 분할 저장, 오류 감지·복구.
- **음성 인식**: 언어 선택, 타임스탬프, 문장 단위 분리, 중복 제거, 잠정/확정 구분, 종료 후 미처리 오디오 처리.
- **번역**: 원문·번역 언어 선택, 문맥 기반, 이전 대사 참조, 고유명사 일관성, 선택 구간 재번역, 모델 교체.
- **오버레이**: 원문+번역 / 원문만 / 번역만, 글꼴·색·투명도·위치, 항상 위, 표시/숨김 단축키.
- **재생 모드**: 저장된 프로젝트나 불러온 SRT를 같은 오버레이로 표시. 영상 소리를 들어 자막 위치를 자동으로 맞추고, 필요하면 수동으로 미세조정 (ADR-006).
- **편집기**: 오디오 플레이어, 파형, 자막 목록, 원문·번역·시간 편집, 분할·병합, 구간 반복, 수정 상태, 자동 저장.
- **내보내기**: 원문 / 번역문 / 이중 자막 SRT (UTF-8). VTT 등 확장 가능한 Exporter.

## 7. 데이터·프로젝트 정책 (불변 규칙)

- 오디오는 영구 보관하지 않는다. 작업 중에는 청크 단위로 임시 저장한다 (전체를 메모리에 올리지 않는다).
- 프로젝트(자막·메타데이터)와 오디오는 독립적으로 관리한다. 오디오가 삭제돼도 프로젝트를 다시 열어 수정할 수 있다.
- **`Exported`와 `Completed`는 같은 것이 아니다.** SRT를 내보내도 오디오를 삭제하지 않는다.
- 임시 오디오는 **사용자가 명시적으로 「작업 완료」를 선택하고 최종 자막이 정상 저장된 경우에만** 삭제한다.
- 상태: Ready · Recording · Paused · Interrupted · Processing · Editing · Completed. 내보내기 여부는 별도 축(없음 / 최신 / 오래됨)이다. (결정 근거: ADR-005)

## 8. 성공 지표 (초기 목표 — Phase 0 기준선 이후 확정)

| 지표 | 초기 목표 |
|---|---|
| 청크 손실 | 2시간 캡처에서 누락 샘플 0. 강제 종료 시 손실 ≤ 2초 |
| 원문 표시 지연 (발화 끝 → 표시) | p50 ≤ 2.5초, p95 ≤ 4초 |
| 번역 표시 지연 | p50 ≤ 4.5초, p95 ≤ 7초 |
| 장시간 안정성 | 3시간 연속, 크래시 0, 메모리 증가 ≤ 5%/h |
| 번역 품질 (일→한 평가셋) | 평균 ≥ 3.5/5, 존대 일치 ≥ 90% |
| 타임스탬프 (최종 패스) | 90%가 ±300ms 이내 |
| 재생 모드 자동 싱크 (가설) | 재생 후 위치를 찾기까지 ≤ 10초, 이후 오차 ±300ms 이내, 되감기 후 재동기 ≤ 10초 |

실시간 결과와 최종 결과의 정확도 목표는 따로 둔다. 실시간이 조금 부정확해도 최종 편집에서 고칠 수 있어야 한다.
