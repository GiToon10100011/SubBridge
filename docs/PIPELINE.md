# SubBridge 파이프라인

> 근거 표시: ✅ 1차 출처 / ◐ 2차 출처 / ❓ 미확인. 지연·정확도 수치는 가설이며 Phase 0에서 기준선을 잰 뒤 확정한다.

## 1. 단계

```text
캡처 ─▶ 링버퍼 ─┬─▶ ChunkWriter ─▶ audio/*.wav            (디스크 우선)
                 └─▶ 리샘플(16k mono) ─▶ VAD ─▶ 실시간 ASR
                       ─▶ Stabilizer(잠정/확정, 환각 필터)
                       ─▶ 실시간 번역 ─▶ EventBus ─▶ 오버레이 / DB

Stop ─▶ Processing: 최종 ASR ─▶ 분절 ─▶ 문맥 번역 ─▶ Editing
```

## 2. 실시간 ASR 전략

whisper.cpp의 공식 stream 예제는 스스로 「naive」라고 밝힌다 ◐. UFAL whisper_streaming(LocalAgreement-2)은 긴 음성에서 지연 3.3초를 보고했다 ✅ (arXiv 2307.14743).

**권고: 발화 단위 인식 + 부분 디코드**

1. VAD(Silero, whisper.cpp 내장 ✅)로 발화 시작·끝을 잡는다. 기본 임계값 0.5, 최소 발화 250ms ✅.
2. 발화가 진행되는 동안 약 1초마다 지금까지의 구간을 부분 디코드 → **잠정(interim)** 결과.
3. 발화가 끝나면 전체 구간을 한 번 더 디코드 → **확정(confirmed)** 결과.
4. 쉼 없는 긴 발화(강의)는 최대 10초에서 끊고 1초 겹친 뒤 경계 중복을 제거한다.
5. 그래도 지연이 문제면 LocalAgreement(연속 두 결과의 공통 접두어 확정)로 전환한다.

드라마는 발화가 짧아 이 방식이 잘 맞는다고 판단한다. 강의·인터뷰에서의 품질은 ❓ — Phase 0에서 평가한다.

## 3. 잠정/확정 결과 처리

| 상태 | 의미 | 표시 | 저장 |
|---|---|---|---|
| interim | 아직 바뀔 수 있음 | 오버레이에 흐리게 | 저장하지 않음 (메모리) |
| confirmed | 발화 종료 후 확정 | 오버레이에 정상 표시 | `Segment(origin=realtime, status=confirmed)` |
| final | 최종 패스 결과 | 편집기 | `Segment(origin=final, status=final)` |

## 4. 환각·잡음 방지 (R6)

Whisper는 무음·BGM에서 「ご視聴ありがとうございました」 같은 문장을 만든다.

- VAD로 음성이 아닌 구간은 ASR에 보내지 않는다.
- `no_speech` 확률과 압축률 임계값을 넘으면 폐기한다.
- 같은 문장이 반복되거나 알려진 상투 문구 목록과 일치하면 `flags=환각 의심`으로 표시한다 (삭제하지 않고 표시 — 편집기에서 사용자가 결정).
- 노래·BGM이 길게 이어지면 `flags=music`으로 묶어 일괄 삭제할 수 있게 한다.
- 이전 문장을 프롬프트로 넘기되, 환각 의심 문장은 문맥에서 제외한다 (오염 전파 방지).

## 5. 백프레셔

- 캡처 콜백: 할당·락·I/O 금지. 링버퍼에 쓰기만 한다.
- ChunkWriter는 ASR보다 우선이다. ASR이 밀려도 디스크 기록은 막히지 않는다.
- ASR 대기열이 N초를 넘으면 **따라잡기 모드**: 오래된 구간의 실시간 인식을 건너뛴다. 건너뛴 구간은 최종 패스가 채운다. 오버레이에 「지연 중」을 표시한다.
- 모든 채널은 크기가 제한된다. 넘치면 오래된 잠정 결과부터 버리고 확정 결과는 보존한다.

## 6. 실시간 번역

- 번역 단위: 문장 끝(。？！) 또는 확정 2줄. 너무 길면 최대 길이에서 끊는다.
- 문맥: 직전 확정 N줄을 같이 보낸다. 소형 모델의 지연을 위해 N은 작게 시작한다 `[튜닝: Phase 3]`.
- 번역 요청은 **줄 ID를 보존**한다 (응답을 줄에 정확히 매핑하기 위해). 응답 형식 검증에 실패하면 1회 재시도 후 `pending`으로 둔다.
- 번역기가 응답하지 않으면 오버레이는 원문만 보이고, 해당 줄은 `Translation.status=pending`으로 남아 최종 패스가 채운다.

### 6.1 TranslationProvider 계약 (자체 엔진 포함, Q1)

어떤 엔진이든 (llama-server의 모델, Ollama, Apple Translation, 클라우드, **자체 번역 엔진**) 같은 계약을 구현한다.

| 항목 | 내용 |
|---|---|
| 입력 | 줄 목록 `[{id, text, start_ms, end_ms}]` · 앞 문맥 N줄(번역 완료분 포함) · 원문/목표 언어 · 스타일 힌트(존대 정책, 호칭) · 용어집(v0.2) |
| 출력 | `[{id, text}]` — 입력 id와 1:1. 누락·중복 id는 오류 |
| 능력 선언 | 스트리밍 여부, 최대 문맥, 배치 크기, 지원 언어쌍, 오프라인 여부, 지연 등급 |
| 오류 | 타임아웃 / 형식 오류 / 용량 초과를 구분해 반환 → 서킷 브레이커 (ARCHITECTURE §8) |
| 식별 | `provider` · `model` · `prompt_version`을 `Translation`에 기록 (재현성) |

자체 엔진을 개발할 때의 전제:
- **평가 하네스를 먼저 만든다.** Phase 0의 평가셋(약 200줄)과 지표가 엔진 교체의 기준이다.
- `EditLog`의 before/after에 기계 번역과 사용자 수정본이 쌍으로 남는다. 개선 신호로 쓸 수 있지만, 대사 원문과 번역은 저작물일 수 있으므로 **학습 데이터로 쓰는 것은 별도 결정**이 필요하다 (RISK_ANALYSIS R12). 기본값은 수집·전송하지 않는 것이다.
- 엔진이 서버형이면 원칙 5(로컬 기본)와 충돌하므로 명시적 동의(옵트인)로만 켠다.

## 7. 최종 패스 (Processing)

1. 저장된 오디오 전체를 최고 품질 모델로 재인식 (모델은 Phase 0 벤치로 결정 — turbo / large-v3 / kotoba-whisper / anime-whisper).
2. 분절: 문장·VAD 경계 기준으로 자막 길이 규칙(줄당 글자 수, CPS, 최소·최대 표시 시간)에 맞춘다.
3. 문맥 번역: 전체 문맥 + 용어집(v0.2) + 10줄 배치.
4. 병합 규칙: `user_edited` 줄은 덮어쓰지 않는다. 사용자가 수정하지 않은 realtime 줄만 final로 교체한다.
5. 각 단계는 Job으로 DB에 기록하고 체크포인트에서 재개할 수 있다.
6. 사용자는 「건너뛰고 실시간 결과로 편집」을 선택할 수 있다 (Q7 확정: 기본은 기다린다).

## 8. 번역 프롬프트 설계 원칙 (일본어 → 한국어)

초기 프롬프트에 반드시 포함할 규칙 (`prompt_version`으로 버전 관리):

- 존댓말/반말은 **화자 관계가 드러날 때만** 바꾸고, 같은 인물에는 일관된 말투를 유지한다.
- 간사이벤, 직장 호칭(課長·先輩), 1인칭 뉘앙스(俺/僕/私)의 처리 정책 `[결정 대기: Q10]`.
- 주어가 생략된 문장은 직전 문맥에서 보충하되, 추측으로 새 정보를 만들지 않는다.
- 고유명사는 첫 등장 번역을 기억하고 이후 같은 표기를 쓴다 (v0.2 용어집으로 확장).
- 감탄사·의성어는 자막 길이를 고려해 짧게.
- 출력은 줄 ID를 유지한 JSON 등 파싱 가능한 형식으로 고정한다.

평가는 약 200줄의 평가셋(존대/반말, 간사이벤, 직장 호칭, 1인칭, 주어 생략, 고유명사, 감탄사)으로 사람이 한다. 보조 지표로 COMET.

## 9. 시간 정확도

- 타임스탬프의 원본은 샘플 인덱스다. Whisper의 단어 단위 타임스탬프는 부정확할 수 있으므로(❓) VAD 경계를 우선하고, 최종 패스 후 편집기에서 사용자가 파형을 보며 조정한다.
- 목표: 최종 패스 결과의 90%가 사람이 맞춘 기준과 ±300ms 이내. v0.5+에서 강제 정렬을 검토한다.

## 10. 재생 모드 싱크 (ADR-006) — 전부 ❓ Phase 0 실험 대상

목표: 영상을 다시 재생할 때 SubBridge가 영상 소리를 듣고 **지금 영상의 위치**를 알아낸다.

| 후보 | 방법 | 장점 | 단점 / 미확인 |
|---|---|---|---|
| A. 오디오 지문 | 캡처(또는 Processing) 때 짧은 구간별 지문을 만들어 저장. 재생 때 들은 소리의 지문을 대조 | ASR 없이 가볍고 빠를 것으로 예상, 언어와 무관 | 구현체·라이선스 ❓. 광고·버전·더빙이 다르면 실패 가능 ❓. 불러온 SRT에는 없음 |
| B. ASR 텍스트 매칭 | 재생 때 실시간 ASR로 대사를 인식해 저장된 자막 텍스트와 퍼지 매칭 | 지문 없는 SRT·다른 버전에도 동작 | 위치를 찾기까지 몇 초 걸림, 비슷한 대사에서 오락 ❓, ASR 상시 구동 |
| C. 수동 | 단축키로 시작·보정 | 단순·확실 | 사용자가 불편하다고 하여 **보정용으로만** |

**기본안**: SubBridge가 만든 프로젝트는 A, 불러온 SRT나 A가 실패한 경우는 B를 쓰고, 항상 C(수동 미세조정)를 함께 제공한다. Phase 0에서 락 시간·오차·오락을 측정해 확정한다. 둘 다 쓸 만하지 않으면 C를 기본으로 바꾸고 사용자에게 보고한다.

**공통 규칙 (기본안)**
- **락 조건**: 연속된 여러 구간이 일치하고 위치가 시간 순서대로 진행할 때만 잠근다. 한 번의 우연한 일치로는 잠그지 않는다 (오락 방지).
- **재동기**: 일치 위치가 시계에서 일정 시간 이상 연속으로 벗어나면 다시 찾는다 (되감기·건너뛰기).
- **정지**: 앱 출력이 디지털 무음으로 이어지면 영상 일시정지로 보고 시계를 멈추는 방안 ❓ (자연스러운 무음 장면과의 구분은 미확인).
- **표시**: 락 전에는 자막을 띄우지 않는다. 락이 풀리면 「다시 맞추는 중」을 작게 표시한다.
- **수동 보정**: `playback_adjust_ms`를 더해서 표시한다. 보정은 재락 이후에도 유지한다.
