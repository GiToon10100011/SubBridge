# SubBridge 구현 계획

> 사용자 제안 순서(캡처 검증 → 청크 저장 → 음성 인식 → 번역 → 실시간 자막 → 편집기 → SRT → 복구)와 비교해 다음을 바꿨다.
> - **Phase 0(기술 검증)** 을 맨 앞에 추가했다 — 핵심 가정(DRM, 지연, 번역 품질)이 틀리면 설계가 바뀐다.
> - **크래시 안전 저장**을 Phase 1로 당겼다 — 복구는 저장 구조에 처음부터 들어가야 한다.
> - **기본 SRT 내보내기**를 Phase 2로 당겼다 — 전체 흐름을 일찍 검증한다.
> 코드는 Phase 0 승인 이후에 쓴다.
> **2026-11-02 갱신**: Q2(재생 모드)·Q3(macOS 26)·Q4(Apple Silicon)·Q6(앱 단위)·Q7(종료 후 기다림)·Q18(자체 오버레이)·Q19(자동 싱크 + 수동 미세조정) 반영. ScreenCaptureKit는 MVP에서 뺐다. **재생 모드의 자동 싱크는 실현성이 확인되지 않아 Phase 0에서 가장 먼저 실험한다.**

## 1. Phase 요약

| Phase | 내용 | 완료 조건 | 크기 |
|---|---|---|---|
| **0 기술 검증** (버리는 코드) | 캡처 방식 비교 · DRM 매트릭스 · ASR 벤치 · 번역 벤치 + 평가셋 · 지연 기준선 · 전체화면 오버레이 · **재생 모드 싱크 실험 (최우선)** | 항목별 ADR, 호환성 매트릭스 | M |
| **1 캡처 + 저장** | CaptureBackend(macOS) · 링버퍼 · ChunkWriter · project.db · 상태(Ready/Recording/Paused/Interrupted) · 레벨·시간 · `.lock` | 2시간 누락 0 · kill -9 복구 테스트 통과 · 권한 거부 시 무음 감지 | M |
| **2 실시간 ASR + 기본 SRT** | VAD · 발화 단위 인식 · 잠정/확정 · 환각 필터 · Segment 저장 · 원문 SRT | 지연 p50 목표 · 무음/BGM 환각 테스트 통과 | M |
| **3 번역** | Provider 인터페이스 · llama-server 사이드카 · 모델 다운로드 · 실시간 번역 · 번역/이중 SRT | 무응답 시나리오 통과 · 평가셋 점수 기록 | M |
| **4 오버레이** | 투명 창 · 3가지 모드 · 스타일 · 위치 · 항상 위 · 단축키 · 마우스 통과 | 전체화면 영상 위에서 표시 (가능한 범위 문서화) | S |
| **5 최종 패스 + 편집기** | Processing(Job·체크포인트) · 목록·편집·시간·분할/병합 · 재생·반복 · 파형 · 자동 저장 · undo · 선택 구간 재번역 · 싱크 맞추기·오프셋 도구 | 1시간 프로젝트 처리 · 편집 중 크래시 후 편집 손실 0 | L |
| **5.5 재생 모드** | 저장된 프로젝트 열기 · SRT 불러오기 · 같은 오버레이로 표시 · 자동 싱크(Phase 0에서 고른 방식) · 수동 미세조정 · `playback_adjust_ms` 저장 | Phase 0에서 정한 락 시간·오차 목표 충족 · 되감기 후 재동기 · 소리가 안 들리는 서비스에서 수동 폴백 | M~L |
| **6 완료 · 안정화** | Exporter 마무리 · 내보내기 상태 · 작업 완료 + 오디오 삭제 · 절전·장치 변경·디스크 부족 · 서명·공증 | 오류 시나리오 전부 통과 · 3시간 소크 · 서명된 빌드 | M |

크기: S ≈ 며칠, M ≈ 1~2주, L ≈ 2~4주 (1인 개발 기준 어림. 확정 일정이 아니다).

Phase 순서(오버레이 4 → 편집기 5)는 유지한다 (Q18: 자체 오버레이가 핵심 기능).

## 2. Phase 0 체크리스트 (❓ 항목 모음)

**① 캡처**
- [ ] Core Audio Process Tap 직접 구현 vs cpal 0.17 루프백 비교 (ScreenCaptureKit는 Q3=26으로 MVP 제외 — 탭이 실패할 때만 재도입)
- [ ] **앱 단위 선택 (Q6)**: Chrome·Safari·Firefox·Arc에서 실제 소리를 내는 프로세스가 무엇인지, 번들 기준으로 묶을 수 있는지
- [ ] 같은 브라우저의 다른 탭 소리가 섞이는지 확인 (탭 단위 불가 안내 근거)
- [ ] 대상 앱을 종료·재시작했을 때 번들 ID로 다시 찾아 이어지는지
- [ ] cpal 루프백이 앱 단위 선택을 지원하는지 확인
- [ ] 출력 장치 변경 시(이어폰 연결 등) 탭이 끊기는지, 자동 재구성 가능한지
- [ ] `NSAudioCaptureUsageDescription` 유무에 따른 동작 (무음 버퍼 재현)
- [ ] 권한 거부/철회 시 무음 감지 신호 확인

**② DRM 매트릭스 (실측)**

| 소스 | macOS 26+ | 비고 |
|---|---|---|
| YouTube (Chrome) | ☐ | 가능 예상 |
| 일본 OTT (Chrome) | ☐ | 가능 예상 ◐ |
| 일본 OTT (Safari) | ☐ | FairPlay — 차단 가능성 ◐ |
| 온라인 강의 사이트 | ☐ | |
| 로컬 플레이어 (IINA/VLC) | ☐ | 가능 예상 |
| Apple TV 앱 | ☐ | ❓ |

결과는 `RISK_ANALYSIS.md`의 매트릭스에 기록한다. **우회 시도는 하지 않는다** — 막히면 「막힘」으로 기록한다.

**③ ASR 벤치** (일본어 드라마·강의 클립)
- [ ] large-v3-turbo vs large-v3 vs kotoba-whisper v2.0 (ggml 변환본 가능 여부) vs anime-whisper (라이선스 확인)
- [ ] Apple SpeechAnalyzer (일본어 자산 설치 성공 여부 포함)
- [ ] Metal 단독 vs Core ML 인코더
- [ ] CER, 실시간 배수(RTF), 메모리

**④ 번역 벤치**
- [ ] 평가셋 약 200줄 작성 (존대/반말, 간사이벤, 직장 호칭, 1인칭, 주어 생략, 고유명사, 감탄사·의성어)
- [ ] Qwen3.5 (2B/4B/9B) · Gemma 4 (E4B/26B MoE) · TranslateGemma · Apple Translation
- [ ] Apple Translation: 일본어→한국어 지원 여부 (`LanguageAvailability().supportedLanguages`)와 언어 자산 설치 UX — 공식 문서에서 일본어·한국어 지원을 확인하지 못했다 ❓
- [ ] **자체 번역 엔진(Q1)을 비교할 수 있는 평가 하네스** — 엔진 종류와 무관하게 같은 평가셋·지표로 점수를 낸다
- [ ] 사람 평가(정확성·자연스러움·존대 일치·고유명사) + 보조 COMET
- [ ] 첫 토큰 지연, 처리량, 메모리

**⑤ 지연 기준선**
- [ ] 단계별 타임스탬프(발화 끝 → ASR → 번역 → 표시) 로깅
- [ ] ASR과 LLM 동시 실행 시 GPU 경합 측정 (Apple Translation 대안 포함)

**⑥ 오버레이**
- [ ] 전체화면 영상 Space 위 표시 (`fullScreenAuxiliary` 필요 여부)
- [ ] 마우스 통과 + 항상 위 조합

**⑦ 기타**
- [ ] Vibe 소스의 시스템 오디오 캡처 구조 검토 (MIT 라이선스 파일 직접 확인)
- [ ] Mac App Store 샌드박스에서 탭 가능 여부 (직접 배포 결정 근거)
- [ ] **8GB 프로파일 (Q4)**: 메모리 상한을 걸어 turbo 양자화 + 소형 번역(또는 Apple Translation) 구성이 돌아가는지 근사 측정
- [ ] macOS 27에서 서드파티 시스템 오디오 API 변경 여부

**⑧ 재생 모드 싱크 실험 (Q2·Q19) — 최우선**
- [ ] 같은 영상을 두 번 재생해 **오디오 지문** 대조가 되는지 (재생 환경·브라우저 차이, 광고·버전 차이) — 위치 찾기까지 걸린 시간, 오차, 잘못된 위치 확정(오락) 횟수
- [ ] **ASR 텍스트 매칭**: 저장된 자막과 재인식 결과의 퍼지 매칭 — 위치 찾기까지 걸린 시간, 오차, 비슷한 대사 구간에서의 오락
- [ ] 되감기·건너뛰기 후 재동기에 걸리는 시간
- [ ] 영상 일시정지를 소리로 구분할 수 있는지 (디지털 무음 vs 조용한 장면) ❓
- [ ] 지문 구현체 후보의 **라이선스**와 CPU 비용
- [ ] 보호된 오디오(소리가 안 들리는 서비스)에서 폴백이 되는지
- [ ] 결과가 나쁘면: 수동을 기본으로 바꾸는 안을 사용자에게 보고

산출물: ADR 5건 확정/수정 + 호환성 매트릭스 + 벤치 결과표.

## 3. 테스트 전략

| 종류 | 방법 | 대상 Phase |
|---|---|---|
| **캡처 정확도** | 타임코드 비프가 든 기준 오디오를 재생 → 캡처 → 샘플 수·상호상관 비교 | 1 |
| **강제 종료 복구** | 녹음 중 `kill -9` 자동화 → 재실행 → 손실 ≤ flush 간격 검증 | 1, 6 |
| **소크 테스트** | 3시간 연속 캡처+ASR+번역, 메모리·CPU 추이 기록 | 2, 6 |
| **환각 회귀** | 무음·BGM·노래 클립 세트에서 오탐 문장 수 | 2 |
| **번역 평가** | 고정 평가셋, 모델·프롬프트 버전별 점수 기록 | 3 |
| **장애 주입** | 번역 서버 kill/지연, 디스크 가득, 출력 장치 변경, 절전 | 3, 6 |
| **상태 머신** | 전이 표 기반 단위 테스트(허용/거부), `Exported ≠ Completed` 불변식 | 1~6 |
| **데이터 무결성** | 편집 직후 프로세스 종료 → 편집 손실 0, 오디오 삭제 중간 크래시 → 재개 | 5, 6 |
| **Exporter** | SRT 골든 파일 비교 (타임스탬프 형식, UTF-8, 줄바꿈, 이중 자막 순서) | 2, 3, 6 |
| **재생 모드 싱크** | 드라마·강의·YouTube 3종을 두 번째 재생하며 락 시간, 락 후 오차, 오락 횟수, 되감기 후 재동기 시간 측정. 조용한 장면·광고가 낀 구간 포함 | 5.5 |

## 4. 불변식 (모든 Phase에서 깨지지 않아야 한다)

1. 내보내기는 오디오를 삭제하지 않는다.
2. 오디오 삭제는 사용자의 명시적 「작업 완료」 + 최종 자막 정상 저장 이후에만 일어난다.
3. 오디오 삭제 후에도 프로젝트를 열어 텍스트를 편집할 수 있다.
4. 캡처 쓰기는 ASR·번역 지연과 무관하게 진행된다.
5. 사용자가 수정한 줄은 자동 처리(최종 패스·재번역)가 덮어쓰지 않는다 (확인 없이는).
6. DRM을 우회하는 코드는 어떤 Phase에도 넣지 않는다.
7. 재생 모드는 프로젝트 수명주기 상태와 오디오 삭제에 영향을 주지 않는다.

## 5. 다음 단계

문서 승인 후 Phase 0 스파이크를 별도 승인으로 시작한다. **첫 실험은 ⑧ 재생 모드 싱크**(자동 싱크 실현성)다. 남은 질문(`PRD.md` §9.2)은 Q1(보류)이고 Q20(지문 보존)은 지문 방식이 채택될 때 정하며, 어느 것도 Phase 0 착수를 막지 않는다.
